# Guide: file attachments (S3 or MinIO)

One guide per optional dependency; the list is in
[docs/README.md](../README.md#set-it-up-the-core-first-then-one-feature-at-a-time).
Words used here are in the [glossary](../glossary.md).

## What it adds

Attach files in the message box (the paperclip, paste, or drop). The agent gets
a short-lived link, signed by muster, on muster's own address. A page's upload
block uses the same store ([pages.md](../pages.md)). [uploads.md](../uploads.md).

## What it needs

- **An S3-compatible store**, one of:
  - the bundled one, the `s3` Compose profile (a maintained MinIO fork, not
    published on the host); or
  - your own (MinIO, AWS S3 or any S3-compatible service), with a bucket and a
    key for it.
- **`MUSTER_PUBLIC_URL`**: every link is written on it, so set up the
  [Tailscale guide](tailscale.md) first.

## Turn it on

In the hub's `.env`, then `docker compose up -d --wait`:

- **The bundled store:** `COMPOSE_PROFILES=s3`, plus two random secrets,
  `S3_STORE_SECRET_KEY` (the store's password, and muster's key to it) and
  `MUSTER_UPLOAD_SIGNING_KEY` (signs the links). muster fills in the rest of
  its store settings itself.
- **Your own store:** no profile and **no** `S3_STORE_SECRET_KEY`; set
  `MUSTER_S3_ENDPOINT`, `MUSTER_S3_BUCKET`, `MUSTER_S3_ACCESS_KEY`,
  `MUSTER_S3_SECRET_KEY` (and `MUSTER_S3_REGION` when it is needed) plus
  `MUSTER_UPLOAD_SIGNING_KEY`. Nothing is filled in for you here. The key's
  policy and the bucket's lifecycle rule:
  [uploads.md](../uploads.md#configuration).

Each line's meaning, lengths and defaults (the upload size and link lifetime
included): [features.md](../features.md#attachments) and
[configuration.md](../configuration.md#muster-server-optional-features).
With an agent, [INSTALL.md, "Optional features"](../../INSTALL.md#step-6-optional-features)
uses this feature as its worked example.

## Check it

- `muster doctor`: in its feature list (on stderr), the `attachments` line
  starts with `ON`: `muster doctor 2>&1 | grep -E '^ +ON +attachments( |$)'`; a partial set
  starts it with `MISCONFIGURED` and names what is missing
  ([cli.md](../cli.md#muster-doctor)).
- `docker compose logs muster | grep -E 'file attachments:|uploads:'`: a line
  saying the bucket answered at boot means muster reached it.
- The paperclip appears in a session's message box.

## Turn it off

1. Remove `MUSTER_UPLOAD_SIGNING_KEY`, `S3_STORE_SECRET_KEY` (or your
   `MUSTER_S3_*` lines) from `.env`, and `s3` from `COMPOSE_PROFILES`.
2. `docker compose up -d --wait`. The paperclip is gone.
3. Compose does not stop a service whose profile you took out: remove the
   bundled store with `docker compose --profile s3 rm -sf s3`. Its files stay in
   its Docker volume (`s3-data` in `deploy/docker-compose.yml`) until you
   delete that too.
